How to submit — only after authorization

The upload is the final step, not a validation method. This project never uploads to DrivenData automatically.

Current status: STOP — no file is approved under the literal duplicate rule. Do not submit the parallel-lane TIFF shown on the executive page.

Before a future upload

  1. Confirm the assigned method lane and use the existing canonical cache/evaluator/writer. Do not use a file from another lane as a new submission.
  2. Run the bounded experiment plan: feature-only leakage canaries; buffered whole-segment holdout with visible-only catalogue features; paired 95% CI against same-evaluator incumbent.
  3. Compare the prediction surface before placement and final dots after placement against every registry raster. If |Spearman| >0.90 or >70% of dots are within 3 px of any one registry raster, log duplicate and stop. No lattice exceptions.
  4. Reopen the final candidate and compare to the official sample template. Install validator requirements with python -m pip install -r requirements-validation.txt, then run python scripts/validate_submission.py --template data/sample_submission.tif --candidate candidate.tif --json audit.json. Check one float32 band, EPSG:32611, 100 m, exact shape/transform, matching footprint, finite in-footprint predictions in [0,1], and null/nodata outside the footprint.
  5. Only after all scientific and format gates pass may a separate selector approve a file. Check the authenticated weekly slot cap; no slot is selected in this research review.

Portal steps after a file is approved

  1. Open the official DOE GEMS competition and choose New submission.
  2. Select exactly the approved single-band `.tif`, or a `.zip` containing exactly one GeoTIFF.
  3. Enter the unique submission name and paste the pre-approved note (no more than 140 characters).
  4. Review the quota displayed by the portal, then submit.
  5. Save the portal receipt tied to the exact TIFF hash. Only that receipt is ORGANIZER-CONFIRMED score evidence.

Official requirements: same CRS, shape and geotransform as the sample; one float32 band; values [0,1]; null/NaN outside bounds. A local format pass alone does not prove portal acceptance or scoring.

Diagnosing “Predicted values must be in range [0, 1]”

That error means at least one value evaluated by the portal is outside the allowed range. Check the saved output itself—not the model's pre-write array—for negative values, values above 1, infinities, NaNs in-footprint, or a nodata sentinel being treated as a prediction. Do not clip blindly; fix the writer or score transform, then rerun the full validator.
