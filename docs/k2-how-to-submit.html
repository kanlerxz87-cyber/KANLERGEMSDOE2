Submission guide

From evidence to upload.

A checklist for a future approved candidate—not permission to upload any current file.

Stop here today

There is no approved TIFF in this project. Do not submit the historical links or a format-only research artifact.

01

Run the scientific gates first

A future candidate needs a single preregistered lane, feature-only leakage canaries, whole-segment buffered hide-and-recover, visible-only catalogue features, pooled HOLDOUT-DTI with a 95% spatial CI, a same-evaluator paired win over the holdout best, and both surface and final-dot checks against the entire registry. A separate selector must approve the weekly slot.

02

Validate the exact saved GeoTIFF

Use one float32 band, the template CRS/shape/transform and values in [0, 1], with no masked or non-finite pixels inside the footprint. The official description specifies null/NaN outside the bounds. Re-open the saved bytes, verify their SHA-256, and keep the validator output. Local validation is not organizer acceptance.

03

Identify the file and short note

Once all gates and the selector pass, use its unique content-bound filename and a note no longer than 140 characters. The current run has no submission name because no file exists.

04

Submit only after approval

On DrivenData, sign in, open the GEMS competition, choose “Make new submission,” select the exact approved .tif or a zip containing one GeoTIFF, paste the short note, verify the current weekly quota, and submit. This project cannot access the account or spend a slot automatically.

If the portal reports a range error

Do not guess that NaN or any other specific cause triggered the previously reported error: the rejected bytes and server diagnostic are unavailable. Re-open the exact file with the automated checker, inspect finite in-footprint values and GDAL masks, and compare its CRS, shape and transform with an authenticated sample. Never silently clip invalid predictions or treat a zero-filled alternative as organizer-approved.

python scripts/check_format.py --candidate path/to/file.tif \
  --template .cache/owner-data/sample_submission.tif \
  --shared .cache/GEMSDOE33 --out evidence/format-check.json

The checker uses the pinned shared validator, adds saved-byte and null-mask checks, rejects external GDAL sidecars for a single-file upload, and always leaves ok_to_submit false. The mirror template is not organizer-authenticated.
