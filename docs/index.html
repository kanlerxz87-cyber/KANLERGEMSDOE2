What can be said about the reported GEMSDOE32 value 0.2778?

USER/OWNER-REPORTED · UNVERIFIED The available file hash and pixel count can be checked, but its leaderboard value cannot be reconstructed from a TIFF or a GitHub mirror. No organizer receipt was verified.

The reference-solution notebook at pinned commit aebe92f7… uses Tversky-loss weights α=0.2 and β=0.8. That supports only the loss-weight convention, not an assertion that this notebook implements the official leaderboard score. Under a neighborhood-overlap objective, thinning can reduce redundant false-positive mass while preserving local coverage; it is a plausible mechanism for why sparse outputs may fare better, not proof of what happened on the private test set.

Withdrawn: a former three-point linear fit was used to infer hidden true-positive counts and the size of the private fault set, and to claim pruned catalogue-near dots were all false positives. Those quantities are not identifiable from three reported score/count pairs. The inference has been removed.

GEMSDOE32's mirrored TIFF contains 37,654 positive pixels and passes the raw full-array format/range check as stored. Its reported 0.2778 value remains unverified. The candidate is a different SHA-256 and does not exactly copy any of the nine audited site files.
