Step-by-step

How to make a submission into the contest

  1. Download the TIFF. Click the GeoTIFF link above (or the ZIP). Confirm the SHA-256 matches the value shown. Do not rename the file — the filename carries the unique content ID.
  2. Verify locally (optional but recommended). The file is single-band float32, EPSG:32611, 3730 × 3292, 100 m grid, values in [0,1], zero NaNs inside the footprint. It matches the pinned sample_submission.tif grid exactly.
  3. Go to DrivenData. Open https://www.drivendata.org/competitions/306/competition-doe-gems/ and sign in.
  4. Submit → Make new submission. Upload the single-band GeoTIFF, or a .zip containing exactly that one TIFF.
  5. Enter the unique name. Use the filename (without .tif) as the submission name.
  6. Enter the note (≤140 characters). Copy the note from the note file above. This helps you tell submissions apart later (e.g. clustering with k=25).
  7. Record the organizer receipt. After upload, save the submission-page receipt (timestamp + exact SHA-256). Only the organizer receipt establishes the live score. A local check does not prove organizer acceptance.
Format rules

What the organizer requires

File format

  • Single-band GeoTIFF (.tif), or a .zip containing exactly one GeoTIFF
  • Float32, one band
  • CRS: EPSG:32611
  • Shape: 3730 × 3292
  • Affine transform: 100 m pixel size, origin (243350, 4508550)
  • Prediction values inside the footprint must be in [0, 1]

Official submission format →

Fixing the "[0, 1]" rejection

If DrivenData returns Predicted values must be in range [0, 1], the file contains a value outside [0, 1] — most commonly NaN outside the footprint, because NaN comparisons are false in a whole-array check.

  • Zeros-outside variant (recommended download): stores 0.0 outside the footprint, so every pixel is finite in [0,1]. Passes a strict whole-array [0,1] test.
  • NaN-outside variant: matches the official footprint-convention text (null/NaN outside bounds) but fails any naive whole-array [0,1] check.

Neither variant is proven to be accepted by the organizer; the zeros-outside variant is the safer choice for the [0,1] error.
