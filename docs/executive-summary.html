1. Generate within the assigned lane

First resolve the full-registry support definition and exclusive lane. Reuse the shared feature cache, evaluator and writer. The repository's guarded commands fail closed while the witness remains decisive.

2. Prove scientific eligibility

Run every feature alone as a leakage canary; use buffered whole-segment holdout, visible-only catalogue features, pixel-exact visible masking and the pooled metric. Require a positive paired confidence interval against the frozen current best.

3. Prove novelty and format

Check surface before placement and final dots against the complete registry. Reopen the exact output and validate one float32 band, exact sample CRS/shape/transform and finite values within [0,1]. Record the SHA-256, a distinct name and a note of at most 140 characters. Format validity is not approval.

4. Separate selector and upload

Only after all gates pass, the separate selector checks the current rules and authenticated weekly allowance. Download the approved exact-byte TIFF (or one-TIFF ZIP), open DrivenData, choose “Submit” → “Make new submission,” select the file and enter its note. Save the organizer receipt tied to the file hash.

Diagnosing the [0, 1] range error

The failed file was not supplied, so its cause is unknown. NaNs, infinities, negative nodata sentinels and out-of-range values are possible causes. The local strict validator checks every decoded pixel, including outside the footprint; it rejects invalid output rather than silently clipping it. Zero-outside is a conservative experiment to avoid nonfinite values, not a guarantee of portal acceptance or an authenticated substitute for the official sample.
