Submission format & the [0,1] error

How to make a valid submission

1. Download the approved TIFF

Use the 36GEMSDOE off-catalogue GeoTIFF linked at the top of this page (or its ZIP). Confirm the SHA-256 before uploading:

0e7e1da78fb80ba3ce0849cd32967836d4f3d73206426d43435fbe3958a446c4

2. Open DrivenData → Submit → Make new submission

Go to the official GEMS competition, select Submit → Make new submission, and upload the single-band GeoTIFF (or a ZIP containing exactly that one TIFF).

3. Enter a unique name and note (≤140 chars)

Use the submission name from the filename and the note from the downloaded note file (140/140 characters). The note helps you tell submissions apart later, e.g. clustering with k=25.

4. Record the organizer receipt

Only an actual submission-page receipt establishes the file’s live score. Save the receipt timestamp and exact SHA-256. A local format check does not prove organizer acceptance.

Fixing the "[0, 1]" rejection: the zero-outside variant stores 0.0 outside the irregular footprint, so the entire array is finite in [0,1] and a strict whole-array (a >= 0) & (a <= 1) check passes. The NaN-outside variant matches the official footprint-convention text but fails any naive whole-array [0,1] test because NaN comparisons are false. Neither variant is proven to be accepted by the organizer; the zero-outside variant is the safer download for the [0,1] error.
