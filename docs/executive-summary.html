How submission will work

Instructions only. No weekly slot was used in this review.

  1. Resolve the protocol and run the gates. With proper authorization, require visible-only catalogue features, every feature canary, buffered comparable holdout with CI, literal full-registry checks before and after placement, and verified current quota.
  2. Use the separate selector. Download only an exact, SHA-identified future file cleared by an independent selector; a local format pass is not approval.
  3. Open DrivenData → Submit → Make new submission. Select the approved TIFF or its single-TIFF ZIP and enter the unique name and note of at most 140 characters.
  4. Record the organizer receipt. Only an actual submission-page receipt can establish a file-linked live score.

Format versus acceptance

The official format specifies a single float32 band in [0,1], EPSG:32611 and the supplied 100 m grid, with null/NaN outside bounds. The mirror’s irregular exterior is NaN; these files store zeros there.

The earlier Predicted values must be in range [0, 1] rejection has no retained rejected-file bytes or organizer diagnosis. A local check does not prove portal acceptance or diagnose that rejection.
