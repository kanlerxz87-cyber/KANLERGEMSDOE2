Release checklist

  1. Confirm the exclusive method lane and canonical shared template. Freeze input hashes, full novelty registry, holdout folds and current best.
  2. Use whole-component buffered hide-and-recover. Construct every catalogue-derived feature from visible faults only; apply pixel-exact visible masking. Run one-feature leakage AUC canaries; investigate any value above 0.90.
  3. Beat the frozen holdout best with pooled DTI and a positive paired 95% CI. Publish evaluator version, withheld-positive count, uncertainty, feature canaries and fold receipts. A holdout value is not a leaderboard estimate.
  4. Pass both pre-placement surface and final-dot comparisons against the complete registry: stop if rank correlation exceeds 0.90 or directional overlap within 3 pixels exceeds 70%.
  5. Write a single-band TIFF using the shared writer and template. Follow the official null/NaN-outside wording; zero-outside portal acceptance remains unverified. Validate interior values, CRS, dimensions and geotransform against the authenticated competition sample; hash the exact upload bytes.
  6. Only the separate selector may promote. Confirm the competition rules and remaining weekly cap on the authenticated submission page. An automated format PASS cannot authorize upload.

Fixing “Predicted values must be in range [0, 1]”

NaN, infinity, negative nodata sentinels, or out-of-range values may cause rejection. Inspect raw pixel values, not display colors. Our strict validator rejects all nonfinite and out-of-range cells across the whole grid; it does not silently clip model errors. The official written format specifies null/NaN outside; a whole-array-finite zero exterior passes a different local profile but its portal acceptance is not established. Do not assert a fix without the rejected bytes and organizer clarification. Reopen and validate the exact written TIFF before release.

python scripts/validate_raster.py candidate.tif data/sample_submission.tif

Validation exit code zero means format-valid only. It does not verify novelty, hidden score, or upload eligibility.

After selector approval

  1. Download the exact TIFF named in the approved run card and compare its SHA-256.
  2. Use a distinct model-derived name; keep its explanatory note at most 140 characters. Do not rename a previous prediction and call it unique.
  3. On the official submission page, choose the TIFF (or a one-TIFF ZIP only if the current portal accepts it), paste the note, and submit within the confirmed cap.
  4. Save the organizer receipt with submission ID, exact file hash and result. Only then use the label ORGANIZER-CONFIRMED.

Portal interaction requires an authenticated account and is not performed by this project. No unverified score, paper, or receipt is fabricated.
