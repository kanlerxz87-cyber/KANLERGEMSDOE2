# Session rules

1. Read `README.md` and the standing brief in it before working. Read `docs/research/hypotheses.md` and `evidence/run-card.json` before modeling.
2. The K2-SCALE lane is **stopped** by the literal registry geometry check. Do not retune it, place dots, write a candidate, or use a weekly slot to bypass that stop. A different future lane or protocol change needs explicit authority and a new frozen preregistration.
3. Never represent owner claims as organizer receipts or proxy DTI as a leaderboard forecast. No file is approved merely because it passes a format check.
4. Use the pinned shared template for holdout, canaries and writing. Its root evaluator has documented fail-open cases in `docs/research/irregularities.md`; do not use affected functions until the shared upstream is fixed and a fresh pin is reviewed. Do not fork or quietly patch the evaluator.
5. Catalogue-derived features must be fold-local; hide whole segments with a buffer, mask visible faults pixel-exactly, pool TP/FP/FN and report a spatial CI. Follow the surface and final-dot uniqueness rules literally, including calibration rasters.
6. No automatic DrivenData login, upload, monitoring or leaderboard scraping. The site may check public GitHub commit freshness only; it must never imply that this verifies scores or eligibility.
7. Keep credentials, large data and derived caches out of Git. Restore hash-pinned owner mirrors via the supplied script; mirrors are not organizer-authenticated. Record all missing permissions and conflicting source claims.
8. Parallel-session artifacts already on main are historical, not K2 results. Do not reactivate quarantined TIFFs: the archived E1 raster fails the literal registered-lattice overlap test (see `evidence/parallel-e1-lattice-audit-20261026.json`). Do not silently overwrite or discard other sessions' evidence.
